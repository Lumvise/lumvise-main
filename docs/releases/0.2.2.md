# Lumvise 0.2.2

Lumvise 0.2.2 improves local text retrieval, makes embedding work visible, and
adds safer folder approvals and HTML navigation to the Full Workspace. This
page describes the release source and verified retrieval pilot. Published
installers and supported platforms are listed on the
[release page](https://github.com/Lumvise/lumvise-main/releases).

## What changed

- **Long-section retrieval.** Nomic Embed Text v1.5 supports 512-dimensional
  vectors with separate document/query tasks. Tokenizer-aware chunks stay within
  the 1,024-token document budget, including prefixes and special tokens. Search
  returns a section once, using its best matching chunk.
- **Recoverable rebuilds.** Search-index rebuilds can continue after yielding or
  restarting. A section's new chunk vectors become visible together after a
  complete publication; unfinished chunks do not replace its previous complete
  vectors. Model/profile identity checks prevent mixing incompatible vectors.
- **Visible embedding work.** The Full Workspace reports live embedding activity
  and progress. The batch interface preserves input order and task/profile
  checks. Managed local ONNX profiles currently retain scalar fallback for
  consistency; no production batching speedup is claimed.
- **HTML previews.** The Full Workspace displays a static HTML preview and can
  focus an unambiguous section heading selected in the inspector. Page scripts
  and remote resources are disabled. Ambiguous headings are not falsely
  highlighted.
- **Connector folder permissions.** Native Allow/Deny prompts and persistent
  per-connector grants support read/index access. Restricted mode is the default;
  autoapproval applies only within user-selected Settings folders, and revocation
  takes precedence.
- **Workspace and Assistant polish.** Phone chat uses the shared Workspace
  layout, narrow-screen project controls stay out of the way, menu taps remain
  available during status presentation, and Canvas errors appear in a
  dismissible dialog. This does not claim completion of a project-persisted
  canvas for forwarded phone requests or a new versioned mobile-shell binary.

## Retrieval pilot

The measured pass completed on 12 November 2026 using 50 fixed FRAMES questions
in seed-7 order over a 190-page mirror of their gold-linked Wikipedia sources.
Each original prompt produced exactly one sequential
`search_semantic_elements` request through the active mounted Lumvise MCP
connection, with `limit: 20` and the baseline's default filters.

Recall at k is the fraction of each question's distinct gold articles found
within its first k ranked semantic-element hits, averaged across questions.
It is not the percentage of questions answered correctly.

| Ranked hits | Saved MiniLM pipeline | Nomic 0.2.2 pipeline |                  Change |
| ----------- | --------------------: | -------------------: | ----------------------: |
| 5           |                 54.4% |                61.5% |  +7.1 percentage points |
| 10          |                 62.8% |                77.7% | +14.9 percentage points |
| 20          |                 70.1% |                87.5% | +17.4 percentage points |

At 20 hits:

- All gold articles were found for 32 of 50 questions, versus 19 previously.
- Recall improved for 24 questions, worsened for three, and tied for 23.
- At least one gold article was found for 49 of 50 questions in both runs.
- The median rank of the first gold article remained one.

All 50 current responses reported vector retrieval and a ready index, with zero
query errors or lexical fallbacks. No difficult or failed question was removed,
and no query reformulation, additional search, reranking, graph expansion,
answer generation or judging was mixed into the measured pass.

### Coverage and verification

The rebuilt index reported 7,318 names, 4,272 HTML text sections and 5,843 chunks,
with no rebuild failures. All 190 files were parsed. Current source-page hashes
matched preflight, and question IDs, order, prompts and gold lists matched the
saved baseline.

The coordinator independently reparsed all 50 raw mounted MCP responses,
checked their exact requests, payloads and sequential timings, and reused the
existing offline scorer. All 15 metric/report tests passed. Raw evidence and
input manifests remain with the benchmark run; they are not bundled into the
application or exposed to answering workers.

### Timing and limits

Median mounted-request latency was 4.276 seconds, with a 3.911–6.741-second range.
The sum of the 50 call latencies was 220.869 seconds, excluding setup and gaps
between calls. These debug-build measurements include MCP, plugin, inference
and storage work. They do not establish release performance, isolated inference
speed or a speedup over MiniLM.

The baseline had incomplete vector coverage. Improvements therefore combine
the model, chunking and restored coverage; they cannot be attributed solely to
Nomic. Historical baseline page hashes were not saved, so byte-for-byte corpus
identity with that earlier run is not independently proven.

This is a small gold-page-only retrieval pilot with substantially fewer
distractors than a full-Wikipedia index. It establishes neither full FRAMES
answer accuracy nor superiority over another participant. The
[original FRAMES study](https://arxiv.org/abs/2409.12941) evaluates end-to-end
multi-hop question answering, which is a different measurement.

## Full comparison preparation

A separate candidate corpus now contains all 2,500 normalized linked-page URLs
required by the pinned reference's predefined 822-question common subset.
The source dataset has 824 rows; the existing exclusions are IDs 141 and 540,
with no additional exclusions. This candidate is a 57,742,088-byte text-only
JSONL with question associations and gold labels kept outside the answering
corpus. It has passed independent URL, schema, ordering, source and hash checks.

The snapshot uses 2,497 records from a pinned October 2024 public dataset and
three source-backed archival repairs. A Category page's membership reflects
fetch time, not necessarily 2024. Its identity is:
`3da358bdaa4c7cc3b9625740c4548544ad8166ae12da7730528ff93490a9ed8f`.

No full scored comparison has run. Reader/judge selection, usage limits,
enforced worker isolation, serving/index capacity and a frozen protocol remain
prerequisites. A future matched comparison must give both systems the same whole
corpus and fixed reader, tools and budgets. The corpus preparation is not a
reproduction of a published historical score.

## Updating

The bundled compiled plugins use **protocol major 8**. Update the host and its
matching bundled plugins together; protocol-7 plugins are incompatible. This
release work does not introduce a database reset or migration. Do not delete
existing data or shared models as an upgrade step.

Changing an embedding model or profile requires rebuilding its derived search
vectors. The phone web Workspace and a native phone-shell binary have separate
delivery/version identities; desktop 0.2.2 does not imply a newly signed mobile
binary. Published installers, checksums and release provenance remain the
authority for what has actually shipped.
